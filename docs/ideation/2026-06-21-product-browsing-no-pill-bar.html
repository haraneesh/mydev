Recommendation 2 — ALL CAPS product names → Title Case; cramped card layout → spacious with distinct weight / price zones

⚠ Before — ALL CAPS names, weight + price crammed on one line
Problems highlighted below ALL CAPS is harder to read (especially for older users). Weight and price are merged into one grey line with no visual hierarchy. Tight gap: 4px between every element leaves no breathing room. "ADD TO CART" repeats the shouting style.

What changed and why
Element Before After
Navigation layers PROBLEM 3 layers visible simultaneously — left sidebar (L1), horizontal pill bar (L2), in-grid section headings (L3). L2 and L3 say the same thing. FIXED 2 layers — left sidebar (L1) for major categories, in-grid section headings (L2) as the single sub-category anchor. Pill bar removed entirely.
Sub-category access PROBLEM Pill bar shows only 6–7 pills then hides the rest behind "+ 8 MORE ▾". Half the category is invisible unless you know to expand. FIXED "Jump to section" TOC shows all sub-categories at once in a small grid panel. No overflow, no hidden items.
Section headers PROBLEM Plain row — no affordance that they do anything. User doesn't know they could scroll to them. FIXED Headers now have a small "↑ top" hint on the right, making it clear they are anchor points and that clicking scrolls back up.
Product names PROBLEM ALL CAPS — harder to read, especially for older users. "FLAT BEANS /AVARAI" feels like shouting. FIXED Title Case — "Flat Beans / Avarai". Easier to scan. Dot separator (·) between weight and price adds breathing room.
Cognitive load PROBLEM Eye has to process: sidebar category → pill bar sub-category → overflow button → then find matching section heading in the grid. 4 decisions. FIXED Eye: sidebar category → "Jump to section" TOC → scroll to heading. 2 decisions. Clear hierarchy, one path.
Card — product name PROBLEM ALL CAPS (text-transform: uppercase). Harder to scan, especially for older readers. "FLAT BEANS / AVARAI" reads as shouting and slows recognition. FIXED Title Case. "Flat Beans / Avarai" is immediately recognisable. Larger font size (0.78 rem vs 0.65 rem) improves legibility at a glance.
Card — weight & price PROBLEM Weight and price on the same line in one uniform grey colour — "250 g, Rs. 55.00". No visual hierarchy; the eye can't jump straight to the price. FIXED Weight on its own line in small grey text. Price on its own line in bold maroon — the brand's primary colour. Scannability improved: you see the price without reading the weight first.
Card — internal spacing PROBLEM Uniform gap: 4px between all elements. Card feels dense; name, price, and button are visually indistinct zones. FIXED Deliberate margins: 9 px below image, 6 px below name, 9 px above button. Three clear zones — image · name + price · action — make the card scannable in one glance.
Quantity — model PROBLEM Native <select> implies both "which size" and "how many" are variable. Conflating the two makes the interaction model unclear — what exactly is the user choosing? FIXED Quantity is always 1. The only decision is which pack size. Removing the quantity concept simplifies the card to a single choice.
Quantity — pack size picker PROBLEM Up to 10 pack sizes (150 g → 5 kg) hidden inside an OS-modal dropdown. The user has no idea what sizes exist until they open it — two interactions minimum (tap to open, tap to select). FIXED A compact trigger button always shows the current size (one row, zero clutter). Tapping opens a full option list inline inside the card — each row shows size + price. No OS picker, no scroll modal. Closes on selection, price updates immediately.
Quantity — remove / undo PROBLEM Trash icon (🗑) with no text label. Older users may not associate it with "remove from cart". Tap target is small (≈ 28 × 28 px). FIXED Plain text "Remove" link below the size trigger — unambiguous at any age, no icon literacy required.

Recommendation 3 — Quantity selection: native OS dropdown → custom size trigger + stepper
